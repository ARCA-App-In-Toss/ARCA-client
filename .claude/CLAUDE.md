# ARCA 하네스 라우터

현재 사용자 요청을 먼저 따른다. 질문·문서 수정·하네스 검토에는 빌드 루프를 시작하거나 진행 상태를 바꾸지 않는다.

## 빌드 시작·재개

- “빌드 시작/이어서 구현” 요청에만 `build-orchestrator`를 사용한다.
- 진행은 `.claude/build-state.json`, 제품 계약의 관할은 `.claude/spec/00_INDEX.md`가 소유한다.
- checklist는 `06 §12`의 **8개 단계**다. 한 단계 안에서 관찰 가능한 작은 작업 단위를 하나씩 구현한다. 단계 전체를 한 번의 컨텍스트에 넣지 않는다.
- 복구 시 가장 앞선 미승인 완료·`manual-review`를 먼저 처리한다. 막힌 항목을 건너뛰어 다음 TODO를 시작하지 않는다.
- 필요한 스킬만 한 번 호출한다. 이미 로드한 스킬을 Read로 다시 열거나 오케스트레이터를 재귀 호출하지 않는다.

## 읽기와 출력

- 현재 phase의 참조 지도에서 이번 작업에 해당하는 절/ID만 선택한다. `rules/source-of-truth.md`의 선택 읽기를 따른다.
- 00~08·docs·DECISIONS 전체를 순회하지 않는다. 같은 세션의 변경 없는 발췌는 재사용하고, 압축 후에는 작업 포인터와 필요한 원본만 복구한다.
- OpenAPI·계약 예시는 허용된 생성/검증 명령으로 소비한다. 명시적 읽기 금지가 있으면 그 제약을 우선한다.
- 성공은 결과·검증 요약, 실패는 원인·해당 로그 위치·다음 판단만 출력한다. 전문 로그·전체 diff·중복 상태 보고는 피한다.

## 공통 불변식

- 첫 실제 UI는 개발용 Mock ACTIVE 승객의 질문→작성→저장→다시 읽기다. 운영 동의·탑승 우회를 배포하지 않는다.
- 화면이 DTO·token·SDK Storage key를 직접 다루거나 wire 계약의 수기 정본을 만들지 않는다.
- timeout·Abort·이탈·조회 부재를 mutation 미적용으로 해석하지 않는다.
- 원문·닉네임·익명 키·token을 URL·로그·분석·artifact에 넣지 않는다.
- 허용된 표현 탐색은 진행하고, 채택 시 담당 명세·에셋 기록을 갱신한다.

## 종료와 사용자 관여

게이트·재시도·상태 형식은 `rules/hooks.md`를 필요할 때 읽는다. Stop은 상태만 확인하며 빌드 검사를 실행하지 않는다. 외부 값/권한·제품 판단·명세 충돌은 재시도 대신 영향과 필요한 답을 한 번에 요청한다. 근거 있는 자동 재수정은 작업 단위당 최대 2회이며, 해결되지 않으면 `manual-review`로 남긴다. 기존 사용자 승인을 다시 묻지 않는다.
