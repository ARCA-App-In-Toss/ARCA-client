# 작은 작업 구현

1. 현재 작업 목표·phase 경로·선택한 F/IX/CPY/OP/MS/API-V를 확인한다. phase 참조 지도 전체가 아니라 이 작업의 담당 절만 읽는다. 범위가 정해져 있으면 00부터 다시 탐색하지 않는다.
2. 관찰 가능한 완료 결과와 현재 위험에 대한 Never 조건을 정한다. 작은 문구/스타일 수정에는 구현을 그대로 복제하는 테스트를 추가하지 않는다.
3. 필요한 port/domain/UI 연결만 구현한다. 입력 보존·결과 미확인·접근성·개인정보·자원 실패 중 영향받는 계약을 함께 다룬다.
4. 필요한 경우 07의 해당 base + typed delta·Clock/scheduler/Storage/network를 사용한다. 08이 지정한 주 검증 층에서 확인하고 같은 assertion을 여러 층에 복제하지 않는다.
5. 변경한 파일과 직접 영향 테스트를 실행한다. 실패는 원인과 실패 위치만 상위 흐름에 반환한다. 독자적인 재시도 루프·full 게이트·리뷰어 호출·COMPLETED 전환은 하지 않는다.
6. 결과·검증·남은 실제 환경 증거·다음 행동만 돌려준다. 이미 확인된 코드/명세는 다시 읽지 않는다.

실제 환경이 없으면 해당 증거를 BLOCKED/NOT_RUN으로 남기며 Mock 성공으로 대체하지 않는다. 시각 탐색은 합성 데이터·Mock에서 비교하고 채택 시 02/03/06 또는 Asset Manifest의 기존 담당 위치를 갱신한다.
